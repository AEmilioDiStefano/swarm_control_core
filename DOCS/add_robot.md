# Add or Update a Robot

Use this guide when adding a new robot or changing an existing robot's drive
hardware.

## Source of Truth

`config/robot_instances.yaml` is the canonical robot registry. A robot should be
declared there once with:

- robot name
- SSH target
- control type
- control interface
- robot-specific tuning overrides

Do not add empty robot placeholders to `camera_profiles.yaml`. Camera entries
are generated by camera discovery on the robot.

Reusable profiles live separately:

- `config/control_types.yaml`: drive behavior profiles
- `config/control_interfaces.yaml`: GPIO/hardware profiles and wiring-doc links
- `~/.config/swarm_control_core/camera_profiles.yaml`: generated camera choices

## Preferred Command

From the robot or a configured workspace terminal:

```bash
cd "$WS"
source /opt/ros/"${ROS_DISTRO:-jazzy}"/setup.bash
source "$WS/install/setup.bash"

ros2 run swarm_control_core add_robot_core \
  --workspace "$WS" \
  --name robot4 \
  --host robot4@legion4.local \
  --control-type diff_drive \
  --control-interface dual_L298N_diff
```

Equivalent source-tree wrapper:

```bash
"$WS/src/swarm_control_core/scripts/swarm_core_add_robot.sh" \
  --name robot4 \
  --host robot4@legion4.local \
  --control-type diff_drive \
  --control-interface dual_L298N_diff
```

The command:

- creates or updates the canonical robot entry
- syncs the runtime robot entry
- refreshes runtime `control_types.yaml` and `control_interfaces.yaml`
- preserves generated `camera_profiles.yaml`
- prints the wiring doc for the selected hardware profile
- launches camera discovery unless `--skip-camera` is used

## Diagnose Stale Config

Run:

```bash
ros2 run swarm_control_core robot_doctor_core --workspace "$WS" --robot robot4
```

or:

```bash
"$WS/src/swarm_control_core/scripts/swarm_core_robot_doctor.sh" --robot robot4
```

If runtime core profiles are stale:

```bash
ros2 run swarm_control_core robot_doctor_core --workspace "$WS" --robot robot4 --repair
```

If the source robot entry is missing and you want the doctor to create it during
repair, provide the selected profiles:

```bash
ros2 run swarm_control_core robot_doctor_core \
  --workspace "$WS" \
  --robot robot4 \
  --repair \
  --control-type diff_drive \
  --control-interface dual_L298N_diff
```

## Camera Profiles

Camera profiles are generated from the robot's actual camera hardware:

```bash
ros2 run swarm_control_core save_camera_profile_core \
  --robot robot4 \
  --camera-profiles ~/.config/swarm_control_core/camera_profiles.yaml
```

`camera_profiles.yaml` does not need an empty `robot4: {}` entry. A missing
camera profile means camera discovery has not been completed yet.

## Robot4 Dual-L298N Example

For the four-channel dual-L298N differential-drive profile:

```bash
ros2 run swarm_control_core add_robot_core \
  --workspace "$WS" \
  --name robot4 \
  --host robot4@legion4.local \
  --control-type diff_drive \
  --control-interface dual_L298N_diff
```
